## 一、现状盘点（已达标项）

- 产品架构：身份×工作模式（教学/学习/研究）、以课程为核心的学习空间（预习/讲堂/作业/复习/模拟/资料/答疑）。
- 知识空间：课程级知识库 + S/A/P 三级资料与审核；RAG 支持课程/等级/所有者过滤与跨语言检索。
- AI 抽象：LLMService / EmbeddingService / RAGService / AgentService / CodeJudgeService 全接口化，Mock↔DeepSeek 可切换。
- 工作流：10 条可追踪工作流（备课/作业闭环/科研综述/预习/讲堂/复习/出卷/评分/诊断/答疑），前端可视化。
- 可信输出：AI 生成标签、参考来源（[S]/[A]/[P] + 页码）、未命中明确标注扩展知识、冲突提示。
- 代码质量：分层清晰（api/services/repositories/models/schemas）、类型完整、45 个测试。

## 三、关键缺口清单

1. 无 RAG 评测集与“3 个典型问题测试案例”的准确性论证（赛题明确要求）。
2. 检索仍为 TF-IDF Mock，未接真实 Embedding + 向量库 + rerank；无检索指标（Recall@k/命中位置）。
3. 多模态仅文本+文件；缺图片/语音输入（PPT 截图、手写题、语音提问）。
4. 无效果验证报告、伦理与安全合规声明、3 分钟演示视频脚本、部署包（Docker/一键离线）。
5. 测验题型以单选/判断/简答/代码为主，缺多选/综合/SQL 题与题库管理、错题本、冲刺计划。
6. 代码评测仍为 Mock；未按赛题“复用成熟判题系统”接入真实沙箱。
7. 知识图谱仅 related_points 字段，缺可视化与前置链驱动的规划器。
8. 学习行为埋点粗（动作+时长），缺页面级/题目级数据；画像置信度未用于推荐。
9. 科研对比/阅读深度有限；缺引用管理与课程↔科研的链路度量。
10. 无审计日志、上传安全（类型/病毒）、备份与 PostgreSQL/向量库迁移路径。

## 四、P0：直接影响评分与演示（优先做）

### P0-1 内容质量与可信：真实 RAG + 评测证据
- 接入真实 Embedding（BGE-M3 / Qwen-Embedding 任一）与向量库（如 SQLite-vec / Chroma，保持 EmbeddingService/RAGService 接口不变）。
- 检索升级：混合检索（关键词+向量）、rerank 步骤、按来源等级加权；建立 `rag_eval.py`：≥30 条学科问题（覆盖 7 门课×章节），输出 Recall@k、命中来源等级分布。
- **典型问题测试案例（3+）**：生成《测试案例与准确性论证》文档——每题给出问题/引用来源/回答/与标准依据对照/局限，作为内容质量度材料。

### P0-2 多模态交互（赛题技术实现建议第 5 条）
- 新增 `VisionService` 抽象（图片理解：PPT 截图/手写题/教材页），预留语音（ASR/TTS）接口。
- 答疑支持图片输入：DeepSeek 不支持视觉时给出建议 API（如智谱 GLM-4V / Qwen-VL）并保留 provider 切换位。
- 课程资料上传支持 PPT/PPTX/Word 解析（python-pptx、docx），进入“资料→知识点→学习内容”管线。

### P0-3 智能工作流编排深化
- 工作流定义可视化（步骤/分支/审批配置页），运行指标（耗时/成功率）、失败重试、人工审批通知。
- 演示链路固化：“AI 教学设计 → 发布作业 → 学生提交 → 评测/批改 → 学情 → 教学诊断 → 采用建议 → 更新教案”一键闭环演示。

### P0-4 交付材料（完成度/用户认可度）
- `docs/DEMO_SCRIPT.md`：3 分钟视频脚本（开场定位→教师闭环→学生闭环→科研↔课程互跳）。
- `docs/EFFECT_REPORT.md`：2 名真实用户（标注身份）试用反馈与结构化记录；小样本对比（如 AI 备课耗时、答疑采纳率）。
- `docs/ETHICS.md`：伦理与安全合规声明（不侵权、AI 内容标识、不伪造数据）。
- 部署：Dockerfile + docker-compose（backend/frontend/数据卷），一键离线演示包与启动脚本。

## 五、P1：功能深度（技术实现度/内容质量）

### P1-1 知识库与知识图谱
- 知识点四层关联：课程→章节→知识点→资料/题目/论文；新增 `related_points` 可视化（前端图谱）。
- 资料审核完善：教师端“RAG 使用统计”（命中次数/来源等级占比）、待审核提醒。
- OCR 增强：表格/版面识别（如 PaddleOCR 版面）、扫描教材章节自动拆分建议。

### P1-2 学习闭环深化
- 题库管理：多选/判断/简答/代码/SQL/综合分析题型；教师可建题，章节测验/模拟/错题重测共用题库。
- 错题本 + 冲刺计划：按知识点聚合错题与错误模式，考前生成倒计时计划。
- 行为埋点：题目级答题记录、页面停留、预习/复习完成状态 → 画像置信度提升。

### P1-3 代码评测真实化
- 复用车位现有 OJ（`NUS/codecrucible` judge-worker）或 Docker 沙箱，实现 `CodeJudgeService` 真实实现（接口不变），支持 C/C++/Java/Python 编译运行、内存/时间/沙箱隔离。

### P1-4 科研深化
- 论文对比结构化数值化（方法/指标表）、引用管理与导出；研究方向画像。
- 课程↔科研链路：知识点相关论文推荐理由可解释；“深入研究/回到课程知识”统计与推荐强化。

## 六、P2：工程化与可推广

- 数据：SQLite→PostgreSQL 迁移脚本 + 备份；向量库独立；`.env` 全配置化。
- 安全：上传类型/大小/内容校验、审计日志、RBAC 矩阵文档、隐私（学生私有资料隔离验证）。
- 性能：RAG 索引持久化/增量更新、OCR 任务队列、前端路由懒加载与包体积控制。
- 可观测与测试：关键 Service 单测覆盖率提升、API 集成测试扩展、端到端冒烟脚本（已有 `scripts/smoke.py`）扩展至全部新链路、压测报告。

## 八、建议里程碑

1. **两周内（P0）**：RAG 真实化+评测集+3 用例文档；多模态预留；演示材料与部署包。
2. **一个月（P1）**：题库与错题本；知识图谱可视化；真实判题沙箱；科研对比深化。
3. **一个半月（P2）**：PostgreSQL/向量库迁移、安全审计、性能与测试完备。

优先启动 P0-1（RAG 评测证据）与 P0-4（演示交付材料），因为它们同时命中“内容质量度”与“完成度/用户认可度”两个高分维度。
